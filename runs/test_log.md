# 기능 시험 기록 (AIGJ_01_010 박수연, 보드 B)

과제 안내문([jetson_with_vision](https://github.com/AIP-1/jetson_with_vision)) 2장의 시험 ID(T0~T4)별 기록입니다.

- 이 기록의 측정값은 모두 **EmbeddingGemma 2 실습 8~10단계**에서 잰 것입니다. 이 과제를 위해 새로 잰 값은 없고, 숫자는 [results/](../results/)의 원래 기록을 그대로 옮겼습니다.
- 그 실습은 이 과제의 키트(`IP카메라 객체인식 실습/`, `스테레오 거리 실습/`, TensorRT 엔진, MQTT)를 쓰지 않았습니다. 그래서 키트로만 할 수 있는 시험은 **미수행**으로 적었습니다.
- 판정은 안내문의 합격 기준으로 했습니다. 시험 절차가 안내문과 다르면 비고에 적었습니다.

## T0. 공통

### T0-1 ~ T0-6   미수행
- 키트의 `00_probe_stream.py`, `05_view.py`, `02_detect.py`를 쓰지 않아 수신 FPS, 지연 누적, 재연결, glass-to-glass를 재지 않았습니다.
- 참고(판정에 쓰지 않음): 결과는 헤드리스 보드의 FastAPI 웹 화면(:8000)을 노트북 브라우저로 봤습니다. 10단계 앱 화면의 처리 속도는 ankle1 26.7 fps, stereo 23.1 fps, fused 23 fps였습니다.

## T1. 물체 인식

### T1-1 ~ T1-7   미수행
- TensorRT 엔진을 만들지 않았고(PyTorch `.pt`로만 실행), `03_track_count.py`·`04_bench.py`를 쓰지 않았습니다.
- 참고(판정에 쓰지 않음): 8단계 기준선에서 yolo11n(conf 0.5, 1280x720)으로 COCO 물체 7종(휴대폰·노트북·의자·마우스·컵·우산, 모니터는 COCO의 tv)을 비췄고, 모니터를 뺀 6종이 정답 라벨로 나왔습니다. 거리·신뢰도는 기록하지 않아 T1-2 판정에는 쓰지 않았습니다. 검출 속도 15 fps.

### T1-8 개방 어휘   8단계, 보드 B
- 조건: C920 1280x720, 보드 호스트 venv, `app.py --mode yolo` → `relabel` → `yoloe` (yoloe-11s-seg, conf 0.25), LABELS에 테스트 물체 영문 이름 추가
- 결과 (COCO 밖 물체 5종):

| 물체 | yolo | relabel | yoloe |
| --- | --- | --- | --- |
| 무선 이어폰 | remote / mouse ✗ | 무선 이어폰 ✓ | mouse ✗ |
| 천장 에어컨 | microwave ✗ | 미확인 | ceiling air conditioner / microwave △ (각도에 따라 바뀜) |
| 드럼 세탁기 | microwave ✗ | 드럼 세탁기 ✓ | drum washing machine ✓ |
| 선풍기 | clock ✗ | 천장 에어컨 ✗ (목록 추가 전) | electric fan ✓ |
| 모자 | suitcase ✗ | 컵 ✗ (목록 추가 전) | umbrella ✗ |
| **검출 fps** | 15 | 15~17 | 13 |

- 판정: **불합격** (yoloe 5종 중 2종 정답, 기준 4종 이상). 에어컨은 △라 정답으로 세지 않았습니다.
- 비고: yolo는 5종 모두 COCO 80종 중 비슷한 이름으로 틀림(안내문의 기대 결과와 같음). relabel은 목록에 있는 물체(이어폰, 세탁기)를 바로잡았고, yoloe가 틀린 이어폰도 맞혔습니다. 시계는 COCO의 clock이라 5종에서 뺐습니다(yolo clock ✓, yoloe wall clock ✓).

## T3. 행동 패턴 인식   9단계, 보드 B

공통 조건: C920 1280x720, 보드 호스트 venv, yolo11n-pose, `pose_app.py` (`half=True`만 제거). T3-2~T3-5와 T3-7·T3-8의 동작 녹화는 얼굴을 화면 밖으로 빼고 어깨~손목만 보이게 찍었습니다.

### T3-1 관절   미수행
- 정면·측면·뒷면별 관절 신뢰도를 기록하지 않았습니다.

### T3-2 규칙 동작(raw)   일부 수행
- `pose_app.py --raw`로 만세·한팔들기·손 흔들기·악수
- 결과: 만세는 인식되지만 한쪽 손목이 화면 밖이거나 관절 신뢰도가 떨어지는 프레임에서 가끔 한팔들기로 바뀜(깜빡임 발생). 한팔들기·악수는 인식. 손 흔들기는 프레임 하나로는 판정 안 됨.
- 판정: 깜빡임은 확인했지만 **횟수는 기록하지 않음** (안내문은 각 10회와 깜빡임 횟수 기록을 요구)

### T3-3 안정화   일부 수행
- 기본 모드(0.6초 다수결)로 만세·한팔들기
- 결과: 처음에는 한쪽 손목을 자주 놓쳐 만세 비율이 60%를 넘지 못해 만세가 잘 잡히지 않음 → 카메라에서 물러나 두 손이 다 보이게 하자 만세·한팔들기가 따로 안정적으로 인식됨
- 판정: **10회 시험을 하지 않아 판정 못함**

### T3-4 시간 패턴   일부 수행
- 결과: 한 팔을 머리 옆까지 들고 크고 빠르게 흔들면 WAVE로 인식(1.5초 안 방향 전환 2번 이상, 한 번에 어깨너비 15% 이상 움직임). raw에서 안 되던 손 흔들기가 시간 패턴으로 해결됨.
- 판정: **흔들기 10회 / 한팔 정지 10회 시험을 하지 않아 판정 못함**

### T3-5 2인 동작   일부 수행
- 결과: raw 모드에서 악수가 인식됨
- 판정: **악수 5회 / 나란히 서기 5회 시험을 하지 않아 판정 못함**

### T3-6 행동 패턴
- 조건: `pose_app.py --behavior` (규칙), 카메라 눈높이, 얼굴이 보이게 촬영

| 시나리오 (각 3회) | 기대 | 결과 |
| --- | --- | --- |
| 그냥 지나감 | 지나감 | 3/3 |
| 걸으며 2초 봄 | 힐끗 봄 | 3/3 |
| 멈춰서 5초 봄 | 관심 있음 | 3/3 |
| 옆을 보며 15초 서 있음 | 머무름 | 3/3 |

- 판정: **합격** (12회 중 12회, 기준 10회 이상)
- 비고: 응시 시간을 안내문(힐끗 1초, 관심 3초, 머무름 10초)보다 길게(2초, 5초, 15초) 연기했습니다. 기준값 경계 근처는 시험하지 않았습니다.

### T3-7 녹화
- 조건: `pose_app.py --record`, 같은 자리·같은 구도로 동작마다 30~60초

| 파일 | 행 수 |
| --- | --- |
| data/action/idle.csv | 785 |
| data/action/wave.csv | 551 |
| data/action/clap.csv | 610 |
| data/action/arms_crossed.csv | 912 |
| data/behavior/passing.csv | 213 (라벨당 10회) |
| data/behavior/glance.csv | 309 |
| data/behavior/interested.csv | 1101 |

- 판정: **합격** (파일 생성, 프레임당 1행)
- 비고: 녹화 때 FPS를 기록하지 않아 "행 수 ≈ FPS×30"은 확인하지 못했습니다.

### T3-8 학습(B)
- 조건: 동작 4종(idle·wave·clap·arms_crossed) 녹화 → `train_pose.py --data data/action --task action --window 30` → `pose_app.py --model models/action.pt`. 표준편차 하한을 `std.clamp(min=0.03)`으로 바꿈
- 결과: 최고 검증 정확도 **0.989**

| 정답 \ 예측 | arms_crossed | clap | idle | wave |
| --- | --- | --- | --- | --- |
| arms_crossed | 25 | 0 | 0 | 0 |
| clap | 0 | 18 | 1 | 0 |
| idle | 0 | 0 | 26 | 0 |
| wave | 0 | 0 | 0 | 17 |

- 규칙 판정·실시간과 다른 사례:
  - 표준편차 하한 1e-6(원본)에서는 가만히 있어도 wave로 셈. 얼굴을 빼고 녹화해 얼굴 특징이 항상 0이었고, 표준편차가 0에 가까워 정규화 값이 폭주한 것이 원인 → 하한 0.1은 박수가 둔해지고, 0.03 + 박수 30초 추가 녹화에서 4개 동작 모두 실시간 인식
  - 규칙은 손 흔들기를 머리 옆 높이에서만 잡지만, 모델은 가슴 높이 흔들기도 녹화에 넣음(가슴 높이 따로 시험은 안 함). 박수·팔짱은 규칙에 없어 모델만 판정
  - 행동 모델(`--window 15`, 안내 설정 80은 학습 윈도 0개)은 검증 정확도 0.364(검증 윈도가 interested 11개뿐). 실시간에서는 규칙(한글)과 모델(영어) 판정이 확률 0.7 경계에서 번갈아 나옴
- 판정: **합격** (검증 정확도 ≥ 0.85, 불일치 사례 기록)
- 비고: 동작별 녹화 길이가 30~60초로 안내문(60초)보다 짧은 것도 있습니다. 검증 데이터는 같은 녹화의 뒷부분이라 실제 성능보다 높게 나옵니다.

## T4. 거리 측정   10단계, 보드 B, 2026-10-27~28

### T4-0 ~ T4-8   미수행
- 두 카메라를 나란히 붙인 정렬형 스테레오(`스테레오 거리 실습/`의 `s0`~`s3`)는 하지 않았습니다. 두 카메라를 방의 다른 자리에 둔 T4-9 방식만 했습니다.
- T4-1 참고: `usb_stereo_setup.sh` 대신 `v4l2-ctl`로 두 카메라 자동초점을 끔(`focus_automatic_continuous=0`, `focus_absolute=0`). 자동초점을 켠 상태에서는 렌즈 보정 RMS가 1.4~3.5 px로 흔들렸습니다.
