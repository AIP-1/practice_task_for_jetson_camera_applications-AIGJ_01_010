## 과제 2. 물체 인식

### 수행 범위

T1-8 개방 어휘만 했습니다(8단계). COCO 밖 물체를 ① yolo(yolo11n 그대로) ② relabel(EmbeddingGemma 2 임베딩으로 라벨 다시 고르기) ③ yoloe(텍스트로 클래스 지정)로 비교했습니다. TensorRT 엔진, 추적·선 통과, 벤치마크(T1-1 ~ T1-7)는 하지 않았습니다.

### 세 방식 비교 (COCO 밖 물체 5종)

| 물체 | yolo | relabel | yoloe |
| --- | --- | --- | --- |
| 무선 이어폰 | remote / mouse ✗ | 무선 이어폰 ✓ | mouse ✗ |
| 천장 에어컨 | microwave ✗ | 미확인 | ceiling air conditioner / microwave △ |
| 드럼 세탁기 | microwave ✗ | 드럼 세탁기 ✓ | drum washing machine ✓ |
| 선풍기 | clock ✗ | 천장 에어컨 ✗ (목록 추가 전) | electric fan ✓ |
| 모자 | suitcase ✗ | 컵 ✗ (목록 추가 전) | umbrella ✗ |
| **검출 fps** | 15 | 15~17 | 13 |

- 판정: yoloe 5종 중 2종 → **불합격** (기준 4종 이상)
- COCO 안 물체: 기준선에서 휴대폰·노트북·의자·마우스·컵·우산은 정답, 모니터는 COCO의 tv라 따로 봄. 시계는 yolo clock ✓, yoloe wall clock ✓, relabel은 목록에 시계가 없을 때 휴대폰·건전지로 틀어짐

### 오인식 사례

| 물체 | 방식 | 나온 라벨 | 원인 |
| --- | --- | --- | --- |
| 무선 이어폰 | yolo | remote, mouse (각도마다 다름) | COCO 80종 중 하나를 반드시 고름 (닫힌 어휘) |
| 천장 에어컨 | yolo | microwave | 같음 |
| 모자 | relabel | 컵 | LABELS에 모자가 없어 목록 중 가장 가까운 이름을 고름 |
| 시계 | relabel | 휴대폰 / 건전지 | 목록에 없는 물체는 YOLO가 맞힌 것도 망가뜨림 |
| 무선 이어폰 | yoloe | mouse | 작고 비슷한 물체를 헷갈림 |
| 모자 | yoloe | umbrella | 같음 |

### 무엇을 바꿨고 무엇이 달라졌나

- relabel은 목록에 있는 물체(이어폰, 세탁기)를 학습 없이 바로잡지만, 목록 밖 물체는 오히려 틀립니다. → 테스트 물체 이름(hat, electric fan, air purifier, wall clock)을 LABELS에 추가하고 다시 시험했습니다.
- yoloe는 COCO 밖 물체를 이름만으로 찾지만(선풍기, 세탁기) 작고 비슷한 물체는 헷갈리고, 속도는 15 → 13 fps로 조금 느립니다.
- 결론: **yoloe로 후보를 찾고 헷갈리는 물체는 임베딩으로 확인하는 조합.** 과제 5의 타겟 자동 찾기가 이 방식입니다.

## 과제 4. 행동 패턴 인식

### 수행 범위

9단계에서 규칙 동작(raw / 0.6초 다수결 / 1.5초 시간 패턴), 행동 패턴 규칙 시험(T3-6), 녹화(T3-7), GRU 학습(T3-8, 심화 B)을 했습니다. T3-1 관절 시험은 하지 않았고, T3-2 ~ T3-5는 동작이 인식되는지만 보고 정해진 횟수(10회, 5회)로 세지 않았습니다.

### raw vs 안정화

| 동작 | raw (프레임 단위) | 기본 (0.6초 다수결, 1.5초 시간 패턴) |
| --- | --- | --- |
| 만세 | 인식, 한쪽 손목이 화면 밖이면 한팔들기로 깜빡임 | 두 손이 다 보이게 물러서자 안정적으로 인식 |
| 한팔들기 | 인식 | 인식 |
| 손 흔들기 | 판정 안 됨 (한 프레임으로는 든 손과 흔드는 손을 구분 못함) | WAVE 인식 (머리 옆 높이에서 크고 빠르게) |
| 악수 | 인식 | (따로 시험 안 함) |

깜빡임 횟수와 10회 정답 수는 기록하지 않아 T3-2 ~ T3-4 합격 여부는 판정하지 못했습니다.

### 행동 패턴: 규칙 (T3-6)

| 시나리오 (각 3회) | 기대 | 결과 |
| --- | --- | --- |
| 그냥 지나감 | 지나감 | 3/3 |
| 걸으며 2초 봄 | 힐끗 봄 | 3/3 |
| 멈춰서 5초 봄 | 관심 있음 | 3/3 |
| 옆을 보며 15초 서 있음 | 머무름 | 3/3 |

12회 중 12회로 **합격**. 다만 응시 시간을 기준값(1초, 3초, 10초)보다 넉넉하게 연기해서, 경계 근처에서의 정확도는 모릅니다.

### 학습 모델 (T3-8, 심화 B)

| 모델 | 데이터 | window | 검증 정확도 |
| --- | --- | --- | --- |
| 동작 (idle·wave·clap·arms_crossed) | 785 / 551 / 610 / 912 행 | 30 | **0.989** (87개 중 86개, clap 1개를 idle로) |
| 행동 (passing·glance·interested) | 213 / 309 / 1101 행 | 15 | 0.364 (검증 윈도가 interested 11개뿐이라 의미 적음) |

### 혼동 사례 분석

| 사례 | 원인 | 대응 |
| --- | --- | --- |
| 검증 0.989인데 실시간에서 가만히 있어도 wave | 얼굴을 빼고 녹화해 얼굴 특징이 늘 0 → 표준편차 ≈ 0 → 정규화 값 폭주 | 표준편차 하한 `std.clamp(min=0.03)` |
| 하한 0.1에서 박수가 잘 안 잡힘 | 하한이 크면 박수를 구분하는 작은 차이도 둔해짐 | 0.03으로 낮추고 박수 30초 추가 녹화 → 4개 동작 모두 실시간 인식 |
| raw에서 만세 → 한팔들기 깜빡임 | 한쪽 손목이 화면 밖, 관절 신뢰도 하락 | 카메라에서 물러남 |
| 행동 모델 학습 윈도 0개 | 한 번 지나가는 데 1.5~2초, 안내 설정 창은 80프레임 | `--window 15` |
| 같은 사람이 규칙(한글)과 모델(영어) 판정 사이를 오감 | 모델은 5프레임마다 판단하고 확률 0.7 이상일 때만 덮어씀 | 기록으로 남김 (집계가 한글·영어로 나뉨) |
| 손 흔들기를 머리 옆에서만 잡음 (규칙) | 규칙의 높이 조건 | 모델은 가슴 높이 흔들기도 녹화에 넣음 (가슴 높이 따로 시험은 안 함) |

### 무엇을 바꿨고 무엇이 달라졌나

- 프레임 하나 → 0.6초 다수결과 1.5초 방향 전환 판정: 손 흔들기가 판정되기 시작했습니다.
- 표준편차 하한 1e-6 → 0.03 + 박수 추가 녹화: "가만히 있어도 wave"가 사라지고 4개 동작이 모두 실시간 인식됐습니다.

## 과제 5. 거리 측정 (웹캠 2대)

### 수행 범위

정렬형 스테레오(기본, `s0`~`s3`)는 하지 않았고, 두 카메라를 방의 다른 자리에 둔 **방 좌표계 근접 감지(T4-9, 심화 B)** 와 **이동 타겟 TTC(확장 B)** 만 했습니다.

### 보정 품질

| 항목 | cam0 | cam1 | 기준 |
| --- | --- | --- | --- |
| 렌즈 보정 RMS (태블릿 체커보드, 칸 22 mm) | 0.372 px | 0.355 px | |
| 위치 보정 재투영 오차 | 3.78 px | 3.22 px | eg2-lab 목표 3 px (조금 넘음) |
| 검증점 3D 오차 | P1 3.1 cm | P2 3.0 cm | ≤ 0.2 m **통과** |

카메라 간격 약 1.14 m, 높이 1.35~1.41 m, 타겟에서 두 시선 각도 약 23°.

### 실측 오차표 (타겟 원점 기준 거리, m)

| 실제 거리·자세 | ankle1 (1대, 발목) | stereo (2대, 어깨 삼각측량) | fused |
| --- | --- | --- | --- |
| 0.5 서 있음 | 0.56 | 0.61 | 0.63 |
| 1.0 서 있음 | 1.18 | 1.06 | 1.21 |
| 2.0 서 있음 | 2.05 | 2.14 | 2.11 |
| 3.0 서 있음 (17 cm 꺼진 바닥) | 2.77 | 3.05 (자세 앉음 오판) | 3.15 (자세 앉음 오판) |
| 0.81 책상에 앉음 | 1.45 (ID 끊김) | **0.67** | 0.91 |
| 한 카메라에만 보임 (1.81) | - | 사라짐 | 0.55 (single) |
| **fps** | 26.7 | 23.1 | 23 |

### 접근 알람과 이동 타겟

- 알람 시나리오 5개(접근, 이탈, 1 m 경계 서성임, 2 m 옆 지나감, 책상에 앉음) 모두 3/3. 1 m 경계에서 20초 넘게 서 있어도 근접 알람은 한 번만 울렸습니다(히스테리시스 0.2 m).
- `--moving`: 충돌 위험 알람이 근접 알람보다 천천히(약 0.5 m/s) 3초, 보통(약 1 m/s) 약 1초, 빠르게(약 1.5 m/s) 1초 미만 먼저 울렸습니다. `--ttc 3.0`에서는 2.2~2.4 m에서 울렸습니다.
- 헛알람율은 세지 않았습니다. 다만 몸을 돌리거나 앉고 일어설 때 0~1초짜리 가짜 ID가 상자 근처에 생겨 불필요한 근접 알람이 났습니다.

### 무엇을 바꿨고 무엇이 달라졌나

- 사람 위치를 **발목(카메라 1대)** 에서 **어깨 삼각측량(카메라 2대)** 으로 바꾸자, 책상에 앉은 사람(실제 0.81 m)의 거리가 1.45 m(오차 0.64 m, ID 끊김)에서 0.67 m(오차 0.14 m)로 바뀌었습니다.
- 이동 타겟 상자를 카메라 높이 가까이(1.03 m) 들면 한 카메라 추정이 10~14 m로 튀었고, 무릎~허리 높이(약 0.5 m)로 낮추자 안정됐습니다.
- 보정 뒤 cam0이 약 6° 돌아가 타겟이 바닥 아래·8 m 밖으로 잡혔습니다. 보정 때 화면과 비교해 손으로 다시 맞춘 뒤 다시 시험했습니다(비교 이미지 `prox/check/cam_before_after.png`).

## 과제 6. 응용 서비스

**미수행.** MQTT 발행, systemd 서비스, 12시간 가동 기록이 없습니다. 근접 알람·동작 기록은 웹 화면과 HTTP 조회(`/state`, `/events`)까지만 만들었습니다([result_format.md](result_format.md)).

### 개인정보 (실제로 한 것)

- 세 앱 모두 사람 이미지를 크롭·저장하지 않습니다. 8단계는 person 클래스를 크롭에서 빼고(`SKIP_CLASSES`), 9·10단계는 관절 좌표, 바닥 좌표, 알람 기록만 남깁니다.
- 동작 녹화(`data/`)는 관절 좌표 CSV만 저장했고, 영상은 저장소에 넣지 않았습니다.
